# 画面と操作

2026-10-25に本人が採用した画面整理の仕様です。再開の判断と送信条件は
[再開の安全契約](再開の安全契約.md)、受入状況は[実機受入手順](実機受入手順.md)を参照します。

## 一覧に表示するチャット

初期表示は「すべて」です。現在検出できた通常チャットを表示し、
アーカイブ済み、子タスクなどの対象外と、現在検出できない古い記録は表示しません。
全履歴を表示する機能ではありません。実行・監視中の行を優先して並べます。

| 表示 | 意味 |
| --- | --- |
| すべて | 現在検出できた通常チャット。再開処理のない行も含む |
| 解除待ち・再開中 | 制限解除待ち、再開確認中、再開要求済み、再開後を監視中の行 |
| 確認が必要 | `Safe` `Resume`側で安全のため自動再開を止めた行 |
| 再開処理なし | `Safe` `Resume`が再開処理をしていない行。`Codex`側の完了判定とは別 |

過去の利用枠停止が見つかっただけの候補を「解除待ち・再開中」へ混ぜません。
全体が`OFF`なら、行に状態が残っていても自動送信しません。
上部の接続・監視全体に関する確認案内と、特定チャットの確認は区別します。

## チャットを開く

行をダブルクリックするか、選択後に「ChatGPTで開く」を押します。
開く要求だけを渡し、対象指定、監視、完了記録、送信は変更しません。
見出し、境界、空白のダブルクリックでは開きません。

`Mac`は、正規配置先の`ChatGPT.app`とチャットURL対応を確認し、OS標準の
アプリリンクを渡します。起動済みなら再利用し、未起動なら起動します。
表示操作にAppleEventsのオートメーション権限は要求しません。
要求の受付は3秒で判定し、時間切れ・取消し時は所有する補助処理を回収します。
結果は画面内に表示し、他の操作を止めません。自動再試行や別アプリ・ブラウザへの
切替は行いません。受付成功と、実際のチャット到着は別に確認します。
この表示処理は、自動再開の認証・署名検査や送信条件を変更しません。
`Windows`は、照合した公式`Codex`の既存プロセスへ固定のチャット`URL`だけを渡します。
対応を限定した検証候補で、現在の対象は26.1021.3705.0の`x64`版です。
通常のユーザー保存領域だけを対象とし、保存先を上書きした別プロファイルを推測して選びません。
未対応の版、宛先不在、複数の宛先、照合失敗では要求しません。
`Codex`の起動・終了・再起動や、ブラウザによる代替は行いません。
要求の受付と、元のチャットが実際に画面へ表示されたことは別々に検証します。
照合と配送は一つの原子的な操作ではありません。送信後の失敗やタイムアウトを
未送出の証明とはせず、自動的な再送や別経路への切替は行いません。

## 操作を置く場所

「設定」は接続の確認・再設定、利用枠の取得状況、読取り更新、終了に使います。
接続の再設定にはその都度の同意を必要とし、`Codex`の再起動は行いません。
表示項目や並べ替えは一覧の近くに置きます。

個別の対象指定は行の下のチェックで行います。「選択チャットの操作」には、
対象指定、監視の終了・停止、確認後の選び直し、技術情報をまとめます。
「完了として記録」は`Safe` `Resume`側の監視を終了する操作であり、
`Codex`の作業を完了・取消する操作ではありません。
選び直しは既存の確認と世代照合を通し、試行履歴を保持します。

## 実装と検証の計画

1. `app.py`と`tests/test_gui_controls.py`で、表示、操作の配置、行限定の
   開く要求を変更し、旧挙動で失敗するテストから検証する。
2. `thread_navigation.py`と`tests/test_thread_navigation.py`で、固定`URI`、
   起動済みアプリの照合、送出前の拒否と送出後の不明状態の区別、
   情報を漏らさない説明を検証する。
3. 照合は画面スレッドの外で実行する。重複要求を抑え、終了時は取消しと
   処理の回収を行う。既存の再開エンジンと状態`DB`を変更しない。
4. 独立レビュー、関連検査、両`Python`版の回帰検査、実`Tk`の狭い画面検査、
   配布物照合と共通プリフライトを行う。未実施と成功を区別する。
5. 設定・履歴を保持して`Mac`へ配置し、専用会話で画面遷移と実送信経路を
   別々に確認する。自然な利用枠解除など、未達の受入を完了へ繰り上げない。
