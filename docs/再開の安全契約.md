# 再開の安全契約と未達事項

## 採用した処理

自前の`SQLite`で失敗ターン・選択の世代・送信前試行・受領ターンを保存します。同じ失敗ターンに対する試行は一意です。プロセス間ロックと`SQLite`の排他更新で自アプリの多重送信を防ぎます。クラッシュ後の`claim`や応答不明の送信は、期限切れを理由に再送しません。送信の直前から受領保存までは`SQLite`の書込境界を保持します。選択解除が先に確定すれば送信せず、送信確定が先ならその一回の後に選択解除が適用されます。送信中の選択変更がロック待ちで失敗した場合、画面は未適用を表示し、解除成功とは扱いません。

ローカル会話`DB`は一覧と候補検出のためだけに読みます。ターン`ID`の文字順では並べません。送信判断では`bridge`の最新観測と保存した受領ターンを照合します。別ターン、完了、キャンセル、承認待ち、入力待ち、不明状態では停止します。

## 通常モードと接続

再起動前提の自動接続は両`OS`で廃止しました。現在は一覧・利用枠の読取りを提供し、自動再開は未提供です。以下の再開判定と中継の契約は開発用に保持するもので、現行の製品接続が成立したことや送信できることを意味しません。

通常画面の全体`ON`は、現在と今後の通常チャットから利用枠停止を自動で検出する許可です。初期状態は`OFF`で、旧版の選択状態を全チャットへの許可へ勝手に拡張しません。`SQLite`版4へ移行し、既存の試行記録を保持します。全体`OFF`は世代を更新し、送信`transaction`内でも現在の`ON`と世代を再検査します。

自動対象化はローカル`DB`だけで確定せず、`bridge`の最新観測が利用枠失敗・`idle`・待機なしと確認できた対象に限ります。通常の一覧件数の制限と自動検出の範囲を分離します。個別に除外した対象、旧完了行、要確認・不明送信を全体`ON`だけで復活させません。自アプリが受領ターンの正常完了を確認した系列は終了し、その後の別の新しい利用枠失敗だけを、保存済み受領・試行履歴と照合して新しい系列として扱えます。

`Mac`・`Windows`とも、公式`Desktop`を開き直す接続準備、専用起動、起動時の環境変数の注入は提供しません。既存接続へ無停止で接続する方法を再調査します。認証情報の抽出・複製、未知の既存`server`の停止・置換、作業中の`Desktop`の終了は行いません。

`managed`接続の`desktop_binding`は、実`Desktop`から起動された`bridge`による通信の証拠に基づきます。既定の接続は`initialize`要求・成功応答・`initialized`通知の実中継を要求します。`Windows`の明示した接続方式では、公式主接続が`initialized`通知を送らないため、初期化の成功応答を完全に配送した後、許可した読取要求と同じ型・値の`ID`に対する成功応答を完全に配送したことを要求します。初期化応答だけ、早着・別`ID`・エラー・不完全な出力では有効になりません。`initialized_forwarded`は実際の通知の観測値を保存し、通知を生成したり観測済みと偽ったりしません。`nonce`、プロセス開始時刻・実体・祖先、共有`socket`の世代、`CLI hash`、短期`lease`を再照合し、保存`receipt`単体では有効としません。接続証明は読取り専用`DB`接続で検証し、送信の排他更新と競合させません。切断・更新・`PID`再利用・証拠不足なら停止します。

詳細設定の`guarded`接続は、従来の本人による同一共有`server`確認を前提とする互換経路です。機械証拠から本人確認や操作ルール同意を作りません。どちらの経路でも`safe_admission`は`false`のままで、別`writer`との原子的排他は保証しません。再開待ちの手動操作前は`OFF`にする運用が必要です。

接続証明の再検証は、開始時に旧証明が有効であること、新しい全検査が期限内に完了したこと、保存する世代と通信の証拠が同じであることを確認します。検査中に旧証明の期限が切れた場合も、新しい検査開始時刻を使って更新できます。その間の送信判定は古い証明の失効に従って拒否します。期限後に開始した検査や、検査自体が期限を超えた場合は更新しません。送信側も自分の照合終了後に期限を再確認します。

送信対象となった既存チャットだけを読み込み、送信直前に現在の利用枠・利用許可・最新失敗・`idle`・待機なし・変更イベントを再確認します。既存`SQLite`の試行`ID`を`clientUserMessageId`として送り、本文は「続けて」に固定します。この`ID`だけで`server`の冪等性を保証するとは扱いません。受領`turn`が照合できなければ要確認とし、同じ停止を再送しません。

旧中継は`UI`終了後も残る場合があります。更新・削除時は使用中の中継を保護して停止し、会話や`Codex`の設定を削除しません。これは旧版の安全な後処理の契約であり、接続のために公式`Desktop`を再起動する案内ではありません。ログイン自動起動・`managed daemon`／`updater`は追加しません。製品画面への自動入力も採用済みとは扱わず、無停止接続と再開の安全性を別途検証します。[公式`App Server`資料](https://learn.chatgpt.com/docs/app-server)。

## 検証の範囲

`TDD`で受領保存、再制限、正常完了、承認待ち、手動変更、送信応答喪失、再起動、古い`claim`、選択解除、送信直前の変更、利用枠欠損・不正値を検証します。模擬`bridge`は安全な受入能力を持つものとして注入しています。この成功は実`Desktop`接続、`Windows`実機、実際の利用枠解除後の再開を証明しません。

残務の正本は`Issue` #11です。実`Desktop`への安全な送信能力と両`OS`実機`E2E`が確認されるまで安定版・完成扱いにしません。
