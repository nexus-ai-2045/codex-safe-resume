# 開発・検証・公開の正本ルール

## 目的と境界

**本務**: `Mac`・`Windows`の`Codex`デスクトップで、利用枠により停止した明示選択済みの会話を、制限解除後に一度だけ安全に再開し、次回の制限にも継続対応すること。

**非対象**: 利用制限の回避、承認の自動許可、`Codex`本体の変更、無条件の`GUI`操作、作業中の`Codex`の強制終了。

## 正本と意味の整合性

- ソースコード・テスト・仕様の正本は`GitHub` `main`。最新の実施結果・公開状態・残務・担当・次の操作は[実機受入の残務台帳（Issue #5）](https://github.com/nexus-ai-2045/codex-safe-resume/issues/5)。`PR`は未採用の変更候補。
- 状態表示は「実装済み」「モック検証済み」「`OS`実機検証済み」「運用保証」を混同しない。
- ローカルコピーと配布`ZIP`は派生物。差分があれば`GitHub`の`PR`で統合し、履歴に根拠を残す。
- 仕様変更は受入基準を先に更新し、失敗するテスト（`RED`）→最小実装（`GREEN`）→リファクタ（`REFACTOR`）→全`OS` `CI`の順に実行する。

## 安全ラチェット

1. **入力検証**: 異常な制限値、破損`DB`、未知スキーマ、変更されたターンでは送信しない。
2. **状態遷移**: 利用枠待ち→解除検証→一意の送信請求→結果照合→監視復帰。承認待ち・完了・不明は停止。
3. **敵対的レビュー**: 二重起動、クラッシュ境界、競合する`writer`、誤送信、ログへの個人情報流出を確認。
4. **`CI`**: `Mac/Windows/Linux`で単体・回帰テストを実行し、失敗`PR`はマージしない。
5. **実機`E2E`**: `Mac`と`Windows`双方で本当の5時間・週次制限、スリープ・再起動、完了・承認待ちを確認。成功して初めて安定版と呼ぶ。

## 変更案の受入契約

- 対象`Issue`・変更範囲・`RED`を再現する方法・`GREEN`の結果・セキュリティ影響・未検証条件を`PR`へ記載。
- `CI`全ジョブ成功、差分に個人情報・認証情報を含まないこと、レビュー指摘の解消を確認してマージ。
- 開始済みの`GitHub`自動レビューも、最新`HEAD`と同じ`SHA`で完了した結果を回収する。古い`SHA`のレビューや、進行中で指摘がまだない状態を完了扱いにしない。取得できない場合は未確認として阻害要因を記録する。
- 統合直前に現在の`base/HEAD`と全レビューの完了・解決状態を再読する。マージ後にも後着の指摘を確認し、必要な修正を小さな追補`PR`へ戻す。
- `PR`マージ後に `main` の実コードと`README`を照合する。失敗した場合は`Issue`を再オープン。

## 現状の制約

現在のソースには両`OS`共通の公式キュー方式を実装しています。接続のために`Codex`を開き直す処理は撤去済みです。実プロセス・署名・会話保持者・通信相手の確認だけを`OS`固有とし、利用枠・最新ターン・待機・承認・送信・到達照合を共通化します。

保存データベースの候補だけを現在の実行状態とみなしません。起動済み公式アプリの`IPC`から得た所有者・会話・更新番号が一致する状態と、反映済み履歴の最新ターンを照合します。未読込みの会話へ強制的な再開要求を出しません。受付`ID`とターン`ID`を区別し、試行`ID`に対応する実ターンを確認するまでは到達と扱いません。

初期状態は送信せず、接続先と監視中の操作ルールの明示設定を必要とします。全体`OFF`・個別除外・停止後も自分の未処理キューだけを照合・取消できる設計です。取消成功を未到達の証明にせず、不明な試行を自動再送しません。完全同時操作との原子的な排他は保証しません。

## 共通方式の確認状況

2026-10-24時点で、通常の標準入出力接続のまま起動済みの`Windows Codex`に対し、専用試験会話への一度の公式キュー受付と実ターンの応答完了を確認しました。実プロセス→`IPC`→保存履歴の照合も実測しています。再起動・設定変更は行っていません。

自然な利用枠回復後の自動再開、`Mac`実機、両`OS`の配布用画面の受入は未完了です。`Windows`では最終ソースの全テスト、配布候補のビルドと起動を確認しています。変更前の結果を別のソースや配布物へ流用しません。

正常完了の模擬検査、専用会話への一度の要求、画面表示、継続的検査（`CI`）、自然な枠解除後の自動再開を区別します。ローカルの件数だけで全受入成功・運用保証・リモート検査成功・マージ済みとは宣言しません。
## 配布物自身の画面ランタイム診断

`python app.py diagnose --json` は既存の読取り専用診断を使い、画面を開かずに`Tk`の読込みと`Tcl`の初期化を確認します。画面ランタイムが利用できない場合は終了コード1です。会話・接続設定・状態`DB`は作成せず、再開送信もしません。`Windows`の`windowed`配布物で標準出力がない場合も、成否は終了コードで判定します。

両`OS`のビルドは、生成した`GUI`実行ファイルの同じ診断を隔離した一時領域で実行し、失敗時は`Mac`の署名・`DMG`化、`Windows`の`ZIP`化へ進みません。`--help`の成功、署名検査、ビルドツールの成功だけでは画面ランタイムの検証になりません。この診断も実`GUI`・トレイ・実`Desktop`・利用枠解除後の再開の受入を代替しません。
