# `Windows`接続の検証

## 現在の対応と旧方式の廃止

再起動・専用起動・起動時の環境変数の注入によって接続する旧方式は廃止しました。接続のために公式`Desktop`の終了を待つ手順、終了後の開き直し、起動方法の変更は現行の操作手順に含めません。現在のソースには、通常起動済みアプリへの状態照会と公式キュー受付を使う共通方式を実装しています。新方式の`Windows`配布候補はビルドと起動を確認しました。両`OS`の実機受入は未完了です。

過去に専用起動と中継で確認した接続・初期化・同じチャットの読取りは、その旧条件下の実測です。通常起動済みの`Codex`へ無停止で接続できた証拠としては使用しません。旧方式の回帰テストは安全な後処理や既存契約を守るために保持しますが、現行方式の受入成功とは区別します。

## 通常起動済みアプリでの共通方式

公式の`thread/queue/add`へ、本文「続けて」と保存済みの試行`UUID`を`clientUserMessageId`として渡します。公式の`codex queue`と同じ受付処理を使用し、応答の受付`ID`をターン`ID`として扱いません。実ターンへの到達は、試行`ID`と履歴のユーザー入力で別に照合します。

実行状態は、公式アプリのプロセス間通信（`IPC`）から読みます。名前付きパイプの相手を実プロセスの開始時刻・実行ファイル・同一ユーザーと照合し、会話所有者・更新番号・対応版が一致するスナップショットだけを採用します。会話をそのアプリが既に保持していることと、保存履歴の最新ターン・状態も照合します。保存された利用枠エラーだけでは送信を許可しません。

利用枠・最新ターン・待機状態・個別除外・試行記録・送信と到達確認は、両`OS`で共通です。未読込みの会話を強制的に開く要求、承認の自動許可、自動画面入力は行いません。

## 2026-10-24の実測と未達

通常の標準入出力接続で既に起動していた`Windows Codex`を使い、専用試験会話への公式キュー受付一回と、対応する実ターンの応答完了を確認しました。同じアプリについて、実プロセス確認・実行状態の読取り・保存履歴との一致も確認しています。接続のための再起動・設定変更は行っていません。

これは自然な利用枠回復後の自動送信試験ではありません。`Mac`実機、自然な5時間・週次枠の回復、両`OS`の配布用画面の受入は未完了です。旧方式の専用起動・中継での成功を、通常起動の試験結果に含めません。

全体`OFF`や対象除外の後も、自分の未処理キューだけを照合・取消できる設計です。試行`ID`・受付`ID`・入力が一致しない項目は削除せず、削除成功だけで未到達とは判断しません。受付や到達が不明な場合は自動再送せず保留します。

## 既存の実体検証と削除の安全契約

以下は実行ファイルを調べる処理と、旧配置を安全に保持・削除するための契約です。公式`Desktop`の終了や接続切替を許可するものではありません。

## `Microsoft Store`版の確認

保護されたインストール先を通常の権限照合で読めない場合は、実プロセスと`Windows`のパッケージ登録情報を照合します。既知の公式パッケージ、`Store`署名、正常状態、変更可能な配置や外部配置がないこと、内容の完全性、公式実行ファイルの署名がすべて確認できる場合だけ採用します。

キャッシュにある`CLI`の配置が権限検査に通らない場合は、同じパッケージの`CLI`と既知の補助プログラムについて内容の完全一致を確認します。その同じ内容を`Safe Resume`専用の保護された保存先へ準備し、各ファイルへ通常の権限検査と内容の再照合を行います。未知の補助プログラムや変更済みの準備先は採用しません。

準備したファイルは設定と一緒に保持します。設定まで明示して削除する場合は、所有記録と内容が一致する実行環境だけを対象にします。検証したファイルとディレクトリのハンドルを保持して削除し、途中の名前変更で別のファイルを削除しないようにします。未知のファイルや使用中のファイルは保護して停止します。設定全体の削除を一つの原子的な処理として保証するものではありません。

## 開発環境での検査

依存は `packaging/requirements-runtime.lock` の版とハッシュを使用します。通常の`Python`環境は変更せず、仮想環境を使います。

`Windows`の仮想環境では、子`Python`を起動する中継テストに実体の`Python`を使います。仮想環境の起動用プログラムが標準出力を保持する現象を、本番の公式`CLI`の異常と混同しません。リンクの拒否検査には通常権限で作成できる接合点を使い、開発者モードや昇格を要求しません。

一時ファイルの置き場所にも、本番と同じ配置権限の検査が適用されます。検査に通る所有領域を使用し、権限検査を模擬処理に差し替えて合格させません。

```powershell
./packaging/build-windows.ps1 -PythonExecutable <仮想環境のpython.exe>
```

ビルドでは指定した`Python`だけを使用します。省略時は従来どおり `py` を使用します。配布ライセンスと必要な接続モジュールも`ZIP`へ含めます。旧版の`ZIP`に新方式が入っているとは扱わず、最新ソースから生成した配布物で改めて診断・画面検証を行います。

## 実機受入の条件

作業中の`Codex`を終了・再起動せず、設定や起動方法も変えないことを条件にします。試験用チャットと通常のチャットを明確に分け、認証情報や会話を複製しません。旧方式の専用起動・中継接続の成功を、この条件での成功へ読み替えません。

回帰テスト、ビルド、隔離した中継テストだけでは、通常起動済みの公式`Desktop`への接続成功を証明できません。同じチャットへの無停止での要求と応答、完了・承認待ち・入力待ちでの停止、重複送信の防止を個別に確認します。

実際の5時間枠・週次枠の解除は自然な利用条件で検証し、枠を消費するための処理は作りません。未提供の値は補完しません。画面へのアクセス拒否や配置権限の確認不能がある間は、未達の項目を成功や対象外へ置き換えません。
