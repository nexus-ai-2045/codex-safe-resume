# `Codex Safe Resume` の概要

**`Codex Desktop`の利用枠による中断を検出し、対象チャットの再開を目指すオープンソースの補助ツール。** `macOS` / `Windows`向け、日本語`GUI`とタスクトレイ表示に対応しています。

> **開発状況：実験版・両`OS`の実機受入は未完了**
> 現在のソースには、公式のキュー受付（`thread/queue/add`）を使う共通方式を実装しています。`Codex`の再起動・専用起動・接続設定の変更は求めません。`Windows`の通常起動済み`Codex`では、専用試験会話への一度の送信と応答完了、実行状態の読取りを確認しました。自然な利用枠回復後の自動再開、`Mac`実機、両`OS`の配布用画面の受入は未完了です。
> アプリ側の再照合は、別の操作と送信を原子的に排他する保証ではありません。監視対象を手動操作するときは先に監視を停止してください。ローカル結合検査は、実`Desktop`や実際の5時間・週次枠解除後の再開を証明しません。最新の実施結果は[Issue #5](https://github.com/nexus-ai-2045/codex-safe-resume/issues/5)を参照してください。

## V1で先に完成させる範囲

V1は、利用枠で止まった対象チャットを検知し、現在の利用枠で解除を確認して、同じ元チャットへ「続けて」を一度送る機能に絞ります。通常操作は「残量を見る」「全体をON／OFFにする」「対象／除外を確認する」です。手動の完了記録・要確認の選び直し・技術情報は詳細表示へまとめます。

正常完了・承認／入力待ち・手動変更・送信結果不明では停止し、同じ失敗ターンへ重複送信しません。専用会話への手動送信試験と、自然な利用枠停止からの自動再開の実機受入は別です。V1の未達・証拠は[Issue #5](https://github.com/nexus-ai-2045/codex-safe-resume/issues/5)を参照してください。

チャット別プリセット、最大10個の指示、連続実行・ループ、優先設定、UIの全面刷新は、[V2の保留TODO](https://github.com/nexus-ai-2045/codex-safe-resume/issues/10)へ分離しました。これらの画面案は未実装で、V1の完成条件には含めません。

## 目的

利用枠で止まった既存チャットを、回復後に一度だけ再開するための開発用アプリです。起動済み`Desktop`の本人確認、現在の停止状態と保存履歴の照合、公式キューへの受付、実ターンへの到達確認を行います。判定と送信は両`OS`で共通にし、実プロセスや署名を確認する部分を`OS`別にしています。両`OS`の実機受入前であり、完成版の配布ではありません。

## 使い方

`Python 3.11`以降と`Tk`が必要です。`Windows`では `python3` を `py` に置き換えてください。まず `python3 diagnose.py --json` で依存・会話`DB`形式・接続候補を診断できます。診断は実際の送信を行いません。

```bash
python3 app.py gui
```

メニューバー/トレイ機能を使う場合は `pystray` と `pillow`、`App Server`実験連携には `websocket-client` を追加で利用します。以下は版とハッシュを固定した開発・ビルド環境の依存です。導入前に内容と配布元を確認してください。

```bash
python3 -m pip install --require-hashes -r packaging/requirements-build.lock
```

`Mac`で `No module named '_tkinter'` が出る場合は、`Homebrew`版`Python`に対応する `python-tk@<Pythonのバージョン>` の導入が必要です。

接続の準備と確認事項は[接続設定](docs/接続設定.md)を参照してください。 接続変更後などで「要確認」になった対象は、`Desktop`で状態を確認し、「選択チャットの操作」→「確認して選び直す（試行履歴は保持）」で選択解除状態へ戻してから監視対象を選び直せます。同じ失敗への過去の試行記録は保持します。

### テスト

```bash
python3 -m pip install --require-hashes -r packaging/requirements-runtime.lock
python3 -m unittest discover -s tests -v
python3 -m compileall -q app.py core.py desktop_bridge.py watch.py tests
```

### 画面の操作

現在のソースは共通キュー方式へ移行しています。新方式の`Windows`配布候補はビルドと起動を確認していますが、両`OS`の実機受入は未完了のため、既存の配布物で同じ動作ができるとは扱いません。既存の設定や試行履歴は保持し、接続のために`Codex`を開き直したり、専用の起動アイコンを使ったりする操作は求めません。

通常画面の上部にはアカウント共通の5時間・1週間の残量ゲージと回復日時を表示します。未取得・プラン案内で制限なし・古い取得値を区別し、取得できない枠を0％や100％で補いません。取得は60秒ごと、残り時間の表示は通信せず更新し、最終取得から120秒を超えた値や取得失敗時の前回値は「更新待ち」と表示します。

中央は「すべて」を初期表示にし、「解除待ち・再開中」「確認が必要」で絞ります。「すべて」は現在検出できた通常チャットで、全履歴ではありません。アーカイブ済みや子タスクは除外します。「再開処理なし」は本アプリで再開処理をしていない意味で、Codexの完了判定とは別です。行の選択や表示切替では設定を変更しません。下のチェックで個別に除外・復帰でき、全体`OFF`が常に優先します。完了・確認が必要・送信処理中の行は、このチェックで再有効化できません。

全体の状態は「停止中／接続確認中／監視中／要確認」です。設定が`ON`という理由だけで監視中とは表示せず、現在の設定に対応する直近の監視結果を確認します。一覧近くの「詳細表示（プロジェクト・並べ替え）」から表示を増やせます。接続と診断は「設定」、個別の記録操作は「選択チャットの操作」に分けています。`OFF`は`CLI`監視にも適用され、停止した対象や不明な送信結果を全体`ON`だけで復活させません。

再開待ちのチャットを手動で操作する前は`OFF`にしてください。同時操作との原子的な排他は保証していません。一覧・利用枠の読取り、キューへの受付、実ターンへの到達を区別します。共通方式は起動済み`Codex`に接続するため、起動順を切り替える手順はありません。公式アプリが既に読み込んでいる会話だけを対象とし、未読込みの会話を本アプリから起動・再開しません。利用枠・最新ターン・待機状態・送信・到達確認は両`OS`で共通ですが、実プロセス・署名・接続相手の確認は`OS`固有です。詳しくは[接続設定](docs/接続設定.md)を参照してください。

一覧は公式の対話用ソース（`CLI`・`VS Code`・`Atlas`・`ChatGPT`）を対象とし、アーカイブ済み・内部サブエージェント・非対話処理・プレビューが空の行を除外します。正式な表示名を優先し、古い取込み履歴だけで行を表示しません。明示的に除外された監視対象は`OFF`にし、過去の試行履歴は保持します。

実行中・監視対象は一覧の上に表示します。列見出しを押すと、一覧全体の昇順／降順を切り替えられます。一覧近くの詳細表示の「並び順」で優先表示に戻せます。回復予定は数値の日時で並べ、不明な日時は最後に表示します。

画面には公式`CLI`のログイン先の利用枠を、再開送信とは独立して表示します。公式の`account/rateLimits/read`だけを読み、枠の長さに従って5時間・週次を分類し、残量・回復予定・取得時刻を表示します。`API`が返さない枠の残量・回復予定は推測しません。`Mac`の標準配置にある`ChatGPT`同梱`CLI`は未設定時の表示元として使えます。設定済み`CLI`を優先し、版や`hash`の不一致時に別`CLI`へ切り替えません。`Windows`などでは「設定」→「接続を確認・再設定（同意が必要）…」で公式`CLI`を選び、準備を保存すると表示用に読めます。認証は公式`CLI`が管理し、認証情報の抽出・新しいログイン・消費枠のリセット操作は行いません。

一覧の「利用枠の回復予定」は、対象を送信経路で照合して記録した解除待ちの日時であり、送信時刻を保証しません。未取得時は接続確認・自動再開`OFF`・取得待ちの理由を表示し、推測の日時を補いません。両枠が制限中なら遅い方の回復を待ち、解除時に再取得して安全条件を確認します。

「並び順」は一覧近くの詳細表示から変更でき、列名クリックでも昇順／降順を切り替えます。文字列に含まれる数字は2、10の順に並べます。定期更新しても選んだ順序は保持し、回復日時が不明な対象は日時の昇順・降順のどちらでも末尾に置きます。

「設定」の「一覧と利用枠を再取得（送信しない）」は表示だけを更新します。接続修復のために公式`Desktop`を終了・再起動する操作は提供しません。会話・試行履歴の削除や利用枠のリセットは行いません。

表示用のプラン区分・利用枠の読取りと、起動済み`Desktop`の本人確認・送信許可を区別します。5時間枠と1週間枠は常に表示し、`API`実測と確認日付きの公式プラン案内に基づいて「制限あり」「プラン案内では制限なし」「未確認」を示します。料金や契約条件、`API`にない利用枠は推測しません。詳細は[表示と接続の説明](docs/接続設定.md#画面のプラン接続利用枠)を参照してください。

要確認の対象は、公式`Desktop`で状態を確認してから「選択チャットの操作」→「確認して選び直す（試行履歴は保持）」を使います。別の確認画面で同意した場合にだけ監視の選び直しを行い、試行履歴は保持します。通常の表示更新や対象チェックからは実行しません。

`Mac`の常駐アイコンは画面上部のメニューバー、`Windows`はタスクトレイに表示します。起動時は通常ウィンドウを開き、常駐が確認できる場合は×でウィンドウを隠します。アイコンのメニューから再表示・終了できます。`Mac`では`Dock`からも既存ウィンドウを開き直せます。常駐アイコンが使えない場合は画面を残し、「設定」→「アプリを終了」から終了できます。
ノッチのある`Mac`では、メニューバーの項目が多いとアイコンが中央のカメラ領域に隠れる場合があります。この状態では「ノッチに隠れています」と案内し、×でも画面を隠しません。メニューバーの表示項目や配置を調整してください。アプリが他の項目を非表示にしたり、OSの設定を初期化したりすることはありません。


## 制約と安全境界

- `Codex`のデータベースは読み取り専用で参照し、認証情報を`GitHub`へアップロードしません。
- プロセスの一括終了、`Accessibility`権限によるクリック・キー送信、クリップボード操作を行いません。
- 元のスレッドと最新ターンを照合し、不確かな状態では再送信しない設計です。ただし安全性は本番環境では未証明です。
- 利用枠の解除時刻を過ぎても、解除・所有権・ターン完了が検証できなければ自動再開してはいけません。
- 公式`Desktop`が対象会話を保持していることと、プロセス間通信（`IPC`）の相手を確認します。保存履歴だけを現在の実行状態として扱いません。接続できない場合は、別会話の起動・`GUI`入力・認証情報抽出へ切り替えません。
- キューの受付`ID`はターン`ID`ではありません。試行`ID`と実際のユーザー入力・ターンを照合して到達を確認します。受付後に結果が不明でも自動再送しません。
- `OFF`後も自分の未処理キューを照合・取消できる設計です。他の入力は取り消さず、取消成功だけで未到達と断定しません。不明な対象は要確認のまま保持します。
- 再開ターンの受領記録に基づく状態照合を模擬検証しています。正常完了・承認待ち・手動変更では停止し、同じ受領ターンの利用枠失敗だけを次の再開候補にします。実機での繰り返し復帰は未検証です。

## インストールとアンインストール

`packaging/README-portable-ja.md` を参照してください。**ユーザー領域へのファイル配置とショートカット作成**を基本とし、アプリ本体を削除できるスクリプトを提供します。各`OS`・対象版の実施結果と未達は[Issue #5](https://github.com/nexus-ai-2045/codex-safe-resume/issues/5)に記録しています。設定の削除は別操作に分離しています。

更新・アンインストール時は`Safe Resume`本体を通常終了してください。旧版の中継が使われている場合、削除は拒否して保持します。その回収には別途作業の保存と通常終了が必要ですが、接続のための再起動手順ではありません。会話や`Codex`の設定は削除しません。
